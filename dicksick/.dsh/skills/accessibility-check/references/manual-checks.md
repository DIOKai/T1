# Manual state checks

- Keyboard: complete the scoped task using keyboard controls, with a sensible tab order, visible focus and no unintended trap. A modal may constrain focus while open; verify dismissal and return to its initiating control.
- Names and relationships: controls need useful accessible names, labels and state. Check repeated icon buttons in context, form instructions, required fields and errors; placeholder text is not a durable label.
- Structure: headings, landmarks, lists and tables should convey the actual structure. Inspect zoom/reflow and text spacing with the project's target conditions rather than assuming a screenshot proves it.
- Dynamic content: loading, errors, new chat text and completion should be discoverable without stealing focus. Do not announce every streaming token; assess useful announcement units with the target assistive technology.
- Motion/media: include pause/reduced-motion behavior and captions/transcripts when applicable. Do not count an autogenerated transcript as checked without reviewing it.

Record actual inputs, expected behavior, observed result and tested environment. Mark real screen-reader checks unperformed when that environment was unavailable. Automated axe results are one evidence layer, not a replacement for these observations.

Primary guide: [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing). No fixed compliance threshold is embedded here.
