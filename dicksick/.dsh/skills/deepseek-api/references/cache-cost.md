# 上下文缓存与成本

## 使用缓存

DeepSeek 默认启用磁盘前缀缓存。它用于重用输入计算，不是应用对话数据库，也不意味着输入不被处理或保留。

命中要求复用已持久化的完整前缀单元；请求边界、公共前缀检测与固定间隔都可能形成单元。缓存是尽力而为，不能承诺80%或100%命中。

将稳定说明、工具定义和复用资料放在变化问题之前；保持必要顺序与序列化稳定。不要为了命中率保留不再有效的权限、工具或资料，也不要把不同租户身份合并。压缩历史后应重新测量，而不是保证缓存不受影响。

记录 prompt_cache_hit_tokens 与 prompt_cache_miss_tokens，缺失时标记不可用。比较相同任务的调用量、命中、延迟和结果质量；不得为“预热”自行制造付费调用。

[官方缓存机制](https://api-docs.deepseek.com/guides/kv_cache/)

## 成本记录

从当日官方价格表读取模型、币种、每百万 Token 单价、峰谷时间及假日例外。不要把视频的发布时价格或网关估价当实际账单。

估算 = (命中输入×命中价 + 未命中输入×未命中价 + 计费输出×输出价) / 1,000,000。

先核对端点和适配器用量定义；如果推理 Token 已包含在输出计费数内，不再额外相加。搜索、抓取等独立收费能力另计。缺失用量不是零，缺少输入不能给出精确成本。

区分原始供应商 usage、SDK 归一化字段、网关估计与实际扣费。重试也可能产生消耗；跨费率边界的处理不能仅依据网关算法推断供应商计费。

[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
