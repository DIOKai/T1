# 运行时处理与验收

## 流式与结构化输出

使用 SDK 的事件解析器或完整 SSE 解析器；网络块不等于事件或完整 JSON。处理跨块 UTF-8、空行、keep-alive、无 choices 的 usage 事件、空 content，以及 reasoning/content/tool-call 分片。只有参数拼装完成并解析校验后才能请求工具执行。

区分正常结束、长度截断、拒绝/过滤、连接中断和工具调用。中断后的部分内容不是最终结果；不能无声重放整次带副作用的工作流。

JSON 模式仅是格式能力，业务字段仍需本地校验。识别空内容、无效 JSON 和截断；严格工具 Schema 有独立规则，不能把 json_object 等同于任意 Schema 保证。

[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) · [工具及 strict Beta](https://api-docs.deepseek.com/guides/tool_calls/) · [keep-alive](https://api-docs.deepseek.com/quick_start/rate_limit/)

## 工具与 Harness

为每个调用关联响应、工具名、参数、tool_call_id、结果和执行状态。保留模型原始 assistant 消息所需字段，再回传对应结果。设置步数、时限和费用预算。

工具处理器负责路径/网络范围、参数校验与权限；只允许任务需要的工具。对写文件、删除、交易等动作记录幂等状态；重试模型请求不能自动再次执行已完成的动作。未知工具或不合法参数产生受控错误，不执行字符串命令。

API 客户端负责请求/响应；Harness 负责会话、文件访问、工具权限、隔离、差异审查与验证。使用第二模型复核时，只发送授权的最小材料及公开可见结论，不尝试提取代理内部推理。

## 错误与重试

- 400/422：检查参数、协议和历史结构；401：鉴权；402：余额。相同请求直接重试通常无益。
- 429：降低并发并检查账户限额；500/503 或短暂连接故障可按有限预算退避。
- SDK、网关、应用只能有清楚协调的重试预算，避免乘法放大。超时不证明供应商未处理请求。
- 脱敏记录状态、请求标识、模型、延迟和用量。未知或缺失信息保持未知，不把错误响应当正常答案。

[官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)

## 有意义的验收

用模拟记录测试碎片化工具参数、keep-alive、缺失 usage、空正文、截断、未知工具、工具回放与预算耗尽。真实接入验收再检查最小非流式、流式、两轮对话及带工具的思考历史。只有实际运行过的层级可以报告通过。
