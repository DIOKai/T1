# Lua 字节码与混淆分析

依据：[Lua 5.4 手册 load](https://www.lua.org/manual/5.4/manual.html#pdf-load)、[lua.h](https://www.lua.org/source/5.4/lua.h.html)、[lundump.h](https://www.lua.org/source/5.4/lundump.h.html)、[unluac 项目说明](https://sourceforge.net/projects/unluac/)，核对日期 2026-10-17。

普通文本、压缩、标准 Lua 编译块、混淆器自定义虚拟机、LuaJIT/Luau、Cfx 扩展和 Escrow 不共享一个通用解码器。标准签名前缀 1B 4C 75 61 只能给出候选线索；版本/格式字节也可能伪造或截断。先检验实际工具支持，再处理完整结构，不把后缀 .lua 当成源码证明。

unluac 项目说明面向标准 Lua 5.0–5.4 编译块，并列明调试信息等限制。旧视频标题的“Decrypt”不能证明它支持加密文件、所有剥离调试信息的块或任何混淆器。LuaJIT、Luau、自定义 VM 和受保护 Cfx 文件的失败不应靠反复试不匹配版本解决。

若用户要求反编译并已有适用工具，记录工具来源、版本、输入哈希和输出状态，在独立副本与新路径处理；不从视频下载未经核对的 jar/exe。语法可解析仍不证明恢复的程序等价。注释、原始命名和原工程结构可能无法恢复，不能把漂亮格式化称源码还原。

比较控制流、常量、调用、分支和返回路径，保留不确定结构。需要行为核对时只在已隔离的自有合成样例或授权环境进行；不要把未知字节码装进正在运行的游戏服。Lua 手册指出运行恶意构造的字节码可使解释器崩溃，语言层 _ENV/pcall 不能作为完整隔离边界。

遇到 VM 混淆只能先报告静态结构与研究范围；没有还原证据不称“解密成功”。本 Skill 没有内置 unluac，也没有测试真实反编译结果。
