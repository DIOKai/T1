# Escrow 与其他访问问题

[Cfx Asset Escrow 官方说明](https://docs.fivem.net/docs/server-manual/asset-escrow/) 描述了受保护代码/资产和运行授权。服务器能运行资源不表示能直接编辑其受保护源码；正常运行资格、发布者原档、文件权限是不同问题。

资源中的 .fxap、控制台 Escrow 提示和来源说明可形成上下文，但不能据此说每个文件都加密。检查公开可读的 manifest/config/接口与实际错误。作者发布时的 escrow_ignore 选择不受保护文件；在已加密下载包补这一项不等于将现有密文解开。删除 .fxap 或改名也不提供原始源码。

若是用户自己的发布项目，先查原工程/版本历史/备份和作者可编辑原档；若是使用第三方资源，按可读配置、文档 exports/events 或作者提供的源码版本处理具体需求。仅有授权运行报错时先核对账号/服务端授权与资源完整性，不把它当作密码错误，更不能承诺免费解锁器有效。Skill 本身不提供 Escrow 通用解密实现。

Windows 的 Access denied、sharing violation、只读属性、压缩包密码、加密文件系统或损坏包各自排查；PermissionError 只能确认读取失败，不能区分具体原因。不要为“测试”接管整盘权限、关防护或覆盖文件。普通密码恢复也需要匹配具体文件格式和已有凭据，不能套用 Lua 反编译步骤。

输出可读/不可读清单、证据和限制；不能称加密/escrow 部分已完成源码安全审计。公开说明随版本变化，执行时重新核对；本次没有登录账号、上传资源或验证实际授权。
