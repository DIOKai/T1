# 对比与回归

保持同侧进程、构建、硬件、图形条件、资源版本、地图位置和尽可能一致的玩家/实体负载。注明冷启动/缓存预热差异，在相同操作下重复采样，保留样本数、统计窗口及离散程度；不足时不报稳定改善。

比较平均值之外的尖峰/分位数，仅在确有逐帧数据时计算并注明单位和方法。脚本 CPU、帧时间、网络延迟和 SQL 时延各自呈现；不能把客户端帧率改善说成服务器容量提升。

常见回归：按键/交互延迟、绘制闪烁、距离检测遗漏、任务/职业状态、两名客户端看到的实体、所有权迁移、断线、resource stop 清理、NUI 焦点和事件/数据库压力。缓存会失效，静态缓存 player/entity/job 不能替代生命周期处理。

没有统一的“所有循环 Wait(1000)”或“所有资源 0.00ms”标准。逐帧绘制/输入有合理用途；复杂操作应减少不必要频率或工作量，并验证产品行为。

学习资料仍以 [Cfx Profiler](https://docs.fivem.net/docs/scripting-manual/debugging/using-profiler/) 为主。只讲 Windows 设置、画质配置或客户端加帧的软件视频不作为服务器脚本优化证据。本批未找到已完整复现、可替代官方流程的视频，不伪造观看记录。
