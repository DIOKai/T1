# 故障测试与验收

在隔离副本准备确定的初始余额、容量、权限和订单状态。每个场景都比较前后余额、物品、交付记录、重复副作用和玩家反馈，而不是只检查函数没抛异常。

| 场景 | 应检查的结果 |
|---|---|
| 负数、NaN/无穷、超量、客户端改价/目标角色 | 服务端拒绝，相关资产不变 |
| 同一操作重放或两请求同时到达 | 无重复交付/扣款，符合业务次数限制 |
| 通过容量预检查后库存已满 | AddItem 失败被处理，余额/订单可核对 |
| 扣款失败、交付失败、补偿失败 | 无免费物品或静默吞钱；失败/未知状态可恢复 |
| 提交成功但确认丢失 | 重试不盲目重发；能够查证已发生结果 |
| 在扣款/交付/记录边界崩溃或资源重启 | 符合声明的恢复合同，不能声称内存锁提供持久保证 |
| 断线、切换角色、source 被后续玩家重用 | 旧操作不发给新会话/角色 |
| 库存/银行依赖不可用、权限撤销 | 明确失败或待确认，不无限重试 |

仅运行模拟时标明模拟；真实 Qbox、库存和数据库集成必须另验。不可读/escrow 路径写未审查，不能据此给整条业务链通过。

学习：优先读 operation-contract 中的官方接口和事件安全资料。安装演示可看 [Twisle：How To Set Up A Qbox Server](https://www.youtube.com/watch?v=FVfOMuFjoe4)（2026-04-22）或 [Aiden Project Studio：txAdmin Qbox 安装](https://www.youtube.com/watch?v=GAQ6GW1Wl8s)（2026-06-28）。本批仅核对视频元资料/简介，未完整观看或复现；安装演示不证明交易正确性，也不要求重装已有服务器。
