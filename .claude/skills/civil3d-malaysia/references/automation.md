# Civil 3D 自动化：按实际能力选择

同一技能供 Claude Code 和 Codex 使用。没有连接器时仍能讲解、审查导出的数据、写待测试代码；不能声称已经在 Civil 3D 创建或修改对象。

## 选择执行路线

| 路线 | 适用情况 | 先核实 |
|---|---|---|
| 手动操作指导/已授权 UI 自动化 | 单次建模、检查属性、出图 | 活跃图纸、软件版本、当前界面与可用 computer-use 工具 |
| Dynamo for Civil 3D | 重复取值/建模、批量参数与表格 | Dynamo Core、节点/包、Python engine、图纸副本、运行模式 |
| Civil 3D .NET API | 稳定的对象访问、事务化批量处理、自定义命令 | 对应年版/补丁 SDK、运行时、引用 DLL、实际 API 签名 |
| AutoLISP/命令脚本 | 已验证的 AutoCAD 基础操作或可稳定调用的命令 | Civil 对象/API 的可用性；不能以普通 entmake 假装创建完整 AECC 对象 |
| 已安装的第三方 MCP | 用户已选择且连接成功的桥接服务 | 来源、工具清单、进程权限、支持版本、读写能力、实际返回值 |

不要编造名为 `civil3d` 的现成 MCP 工具。此技能不附带 MCP 安装指令，因为本次没有验证可用于用户环境的具体 Civil 3D MCP 项目；不能把 FreeCAD/Blender 的 MCP 命令拿来控制 Civil 3D。以后若用户选择真实 MCP，分别依据其文档配置 Claude Code/Codex，先审查配置改动，不运行来路不明的远程安装脚本。

## Dynamo 版本检查

Autodesk 的 2027 说明记录 Dynamo Core 4.0.2、默认 PythonNet3；2027.1 说明记录 Core 4.1.2。以已安装版本为准，较旧教程中的 Python engine、第三方包和节点名不能直接视为适用。2027 文档中的新旧 pipe/catchment 节点替代关系见来源表。

先做只读枚举/导出的小图；检查对象 ID/名称、单位和空值。修改图纸的图使用 Manual 运行并在副本测试，避免 Automatic 模式意外重复创建对象。明确创建或更新策略及稳定标识，第二次运行不能未经设计产生重复实体。不要自动安装 Dynamo 包、切换 Python engine 或启用不明节点。

## .NET 开发检查

先查对应安装版本的 Civil 3D Developer's Guide 与 SDK。2025 引入 .NET 8 的旧文档不能证明所有后续补丁/2027 都应编译为 .NET 8；Autodesk 后续还有 .NET 10 迁移说明。检查实际产品构建和官方兼容说明后选择 TargetFramework，不自动修改系统运行时。

通常需要 AutoCAD 托管库及 Civil 3D 的 AeccDbMgd 等实际安装引用。每个类、重载、命名空间和返回类型在对应版本参考中核实；不把“看起来合理”的 API 写成已验证示例。

最小开发顺序：读取当前文档与 CivilDocument → 只读列出目标对象 → 明确修改计划 → 按所处上下文取得 DocumentLock/Transaction → 验证输入 → 有界批量修改 → 成功才 Commit。事务/锁要求按当前 API 上下文确认，不用通用示例替代版本文档。

失败时返回对象名/ID、异常、已处理数量和是否提交；保留原图，不通过关闭安全加载或大范围重试规避失败。加载 DLL 前审查代码和目标范围，使用授权的可信路径，不为方便关闭 SECURELOAD 或放宽全局安全配置。

## 最小实际验证

在用户授权的临时图纸副本中验证：

1. 能读取目标 Civil 对象，而不是只有普通 AutoCAD 实体。
2. 一次小范围操作后的数量、几何、坐标、标高与预期一致；记录对象关联。
3. 失败路径不会留下未经说明的部分提交；重复执行行为符合设计。
4. 重建/保存/重开后关联和结果仍正确，适用的 downstream 引用已更新。

本技能初次发布仅经过文档、JSON 检查器与离线场景检查，未附带声称已在 Civil 3D 2027 执行通过的 DLL、Dynamo 图或 DWG。新的执行器必须另做现场验证。
