# Civil 3D 测量、曲面与土方

此处为软件工作流程与质量检查方法，工程阈值来自项目台账。菜单位置可能随版本/语言变化；必要时用当前版本 Help 或实际 UI 核实。

## 点文件到现状曲面

1. 检查 CSV/TXT 的字段顺序、分隔符、表头与单位。PNEZD/PENZD 的 N/E 位置不同。先核对已知点，不能凭坐标数量级自动交换轴。保留源文件和原始点号；Civil 3D 点号若需映射，保留原 ID 对照表。
2. 在 Drawing Settings 检查 Units and Zone。取得水平/竖向基准证据；将“设置 CRS”和“真正转换坐标”分开记录。
3. 从 Points 导入流程选择匹配的 Point File Format；先用少量已知点测试 E/N/Z 和 description，再导入全部。检查重复点、异常高程、编码和控制点，错误点先列清单，不静默删除。
4. 在 Prospector 建立用途明确的 Point Groups。EG/OGL 只引用适合地面建模的点；树顶、建筑顶等点是否排除要依据测量代码。不要用 `_All Points` 无差别建立地形。
5. 建立 TIN Surface，在 Definition 中加入经核验的点组/数据、breaklines 与边界。检查 TIN 三角网，尤其是沟渠、墙、路缘、凹边界及测量空洞。Contours 的外观不是精度证明。
6. 用已知控制点和独立高程抽查，报告差值及项目容许值。不能用同一批建模点的完全吻合来宣称独立精度验证。

## 平台、Feature Lines 与 Grading

先确认平台/门口标高、排水方向、边坡、挡墙、用地边界和接驳条件。检查 Feature Line 的 Site 归属及交点标高影响；隔离需要独立控制的设计对象，避免无意改变已确认标高。

使用项目批准的坡比或坡率。明确 `1V:3H`、`3H:1V`、百分比和角度各自含义；不直接把“1:3”当成软件期望输入。

以 Feature Lines/Grading Group 或其他适合的 Civil 3D 对象建立设计面。审查 infill、daylight、target surface 和曲面定义顺序；不得为“挖填平衡”擅自抬降已获批的道路、平台或排水控制点。

## 土方数量

1. 明确要比较的物理界面：原始地面、剥土后地面、formation/subgrade 或最终完成面。路面 Top 不能无条件当成土方 formation。
2. 对一般现状/设计比较，TIN Volume Surface 的 Base 选现状，Comparison 选设计；设计/竣工对比则按要表达的差值方向另行说明。反选会颠倒结果含义。
3. 指定共同有效范围和明确的计算边界；剔除有证据的空洞/无测量范围，检查两面实际重叠。不要把缺数据区自动补平。
4. 在 Volumes Dashboard 或相应报告中分别记录 Cut、Fill、Net，注明净值约定；对颜色图检查升降含义，避免仅凭红/蓝判断挖填。
5. 先提供未调整的几何体积。只有有项目来源时才另算膨胀、压实、损耗；不能把软件 Cut/Fill Factor 与另一个表格再次重复乘算。说明 bank/loose/compacted 的体积基准。
6. 表土、软弱/不适用料、换填、材料分层及外运/借土按计量范围分别列出；不要将一个表面体积直接当作所有 BOQ 项目。

抽查：完全相同的两面在同一范围几何差量应为零；简单平行面例子可用面积乘高差交叉检查。断面平均端面积和 TIN 体积方法可能不同，记录方法和采样间距，不强迫数字相等。重建后检查原始来源、曲面边界、数量日期与对象名。

## 交付检查

至少针对已请求范围交付：点导入映射、EG/设计面来源、TIN/边界检查图、关键 spot levels 或断面、计算边界与数量表。说明未核验的测量/地勘输入，保留源文件，输出新版本 DWG。
